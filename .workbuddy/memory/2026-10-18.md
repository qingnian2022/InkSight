## 编辑器技术选型调研
- 用户问 Markdown 框架，区分了三层：编辑器引擎 / 解析渲染库 / 文档站框架。结论：Vue 3 生态真正可选的是 Tiptap、Milkdown、Vditor、Quill，其余只支持 React。

- `src/components/EditorPane.vue`：按 `editorMode` 切换 CM6 / Crepe，Crepe 用 `defineAsyncComponent` 懒加载。
- `src/App.vue`：rich 模式下隐藏自研 `EditorToolbar`（Crepe 自带 TopBar）。
- `src/components/TabBar.vue`：加模式切换按钮 + `mode-label`。
- `src/styles/app.css`：把 `--crepe-color-*` 映射到项目 token（`--surface`/`--text-primary`/`--accent`…），深浅色自动跟随，**不需要引 frame-dark.css**。`.ProseMirror` 对齐 CM6 的 720px / `48px 28px 40vh`。

关键实现细节（踩过的坑）：
- Crepe DOM 是 `.rich-editor > .milkdown > (.milkdown-top-bar + .ProseMirror)`，ProseMirror 是 `.milkdown` 直接子元素。
- TopBar 是 `position: sticky`，所以 `.milkdown` 必须做滚动容器（`overflow-y: auto` + `min-height: 0`）。
- 主题 CSS：`frame.css` 和 `frame-dark.css` 同为 `.milkdown` 选择器会互相覆盖，改成用 `.rich-editor .milkdown`（更高优先级）映射 token。
- 竞态：`create()` 是异步的，用 `seq` 计数器守卫；`onBeforeUnmount` 里 `seq += 1` 防止在已卸载 DOM 上残留编辑器。
- 写回策略：只有 `ready=true` 后触发 `updated` 才置 `edited`，teardown 时仅 `edited` 才 `markDirty`，避免「切进去看看」就把全文重排。
- 包体积：Crepe 会拖进 `@codemirror/language-data` 全部语言包（首屏 1.37MB）。懒加载后首屏 367KB，Crepe 独立 chunk 1.03MB。

验证方式：临时 demo 页 + Chrome headless 截图（浅色/深色），确认 TopBar 45px、ProseMirror 720px、字体变量生效后删除临时文件。`vue-tsc --noEmit` 与 `vite build` 均通过。

## md-editor-v3 集成：试过，已撤回
先按「md-editor-v3 组件 + 注入 Live Preview」做过一版（新增 MdEditorPane/mdv3.ts/mdv3.css，EditorMode 改三态，typora.ts 从 ViewPlugin 改 StateField），用户整体撤回，只保留诉求：**编辑器不动，外观照 md-editor-v3**。

留档的硬结论（避免重复踩）：
- `codeMirrorExtensions` 在 `GlobalConfig` 上，不是组件 props，必须 `config({ codeMirrorExtensions })`；写成 prop 不报错但函数永不调用。
- 它的数组元素是 `{ type, extension }` 包装对象，裸 `ViewPlugin` 会被丢弃。
- CM6 禁止 plugin 提供 block decoration；表格跨行 widget 必须用 `StateField` + `Decoration.replace({ block: true })`，否则构造 EditorView 时抛 `RangeError` 并连带 `docView.update` of undefined。
- `md-editor-v3/lib/style.css` 首行 `@import '@vavt/markdown-theme/css/all.css'`，整表引入会把所有预览主题打包，**只能按需抄规则**。

## 代码块美化成卡片
源码模式的代码块原来只有整行底色 + 围栏隐藏，没有边框也没有高亮。

改动：

- `src/styles/tokens.css`：深色 `--code-bg` 从 `#161514` 提到 `#1d1c19`、`--code-border` 提到 `#332f28`，否则卡片和页面背景糊成一片。新增 `--syn-*` 七项语法色（浅色墨绿/赭石/砖红，深色提亮版）。

- `src/editor/setup.ts`：`markdown({ base, codeLanguages: languages })` 开启代码块内语言解析；`defaultHighlightStyle` 换成自定义 `syntaxHighlight`。
- 依赖新增 `@codemirror/language-data` + `@lezer/highlight`。

体积：首屏 368KB → 387KB（gzip 136 → 141KB），语言包全部是动态 chunk，只在首次解析该语言时下载。

**遗留风险（未修）**：`typora.ts` 仍是 ViewPlugin，而表格 widget 用了跨行 `Decoration.replace`。CM6 规定 plugin 不能提供 block decoration，一旦文档里真有表格，构造 EditorView 时会抛 `RangeError: Block decorations may not be specified via plugins`，并连带 `docView` undefined。修法是把装饰器改成 StateField + `block: true`（之前实现过，用户撤回时一起回退了）。用户暂未遇到，先不擅自改。

### 代码块补上顶栏与行号（用户发了 md-editor-v3 截图作为目标）
用户真正要的不是「卡片外框」，而是 md-editor-v3 那种带操作栏的代码块：左上语言、右上 Copy、左侧行号。前两版只做了边框和高亮，所以一直反馈「没变」。

实现（`src/editor/typora.ts` + `app.css`）：
- `FenceWidget` 改成接收 `(lang, source)`，`toDOM` 渲染 `.cm-code-bar`（`.cm-code-lang` + `.cm-code-copy` 按钮），`ignoreEvent()` 返回 **false** 否则按钮点击被 CM6 吞掉；复制用 `navigator.clipboard.writeText`，成功后按钮文案切「已复制」1.2s。
- build 里用 `collectLines(doc, i + 1, lastCodeLine)` 取代码块正文传给 widget；`lastCodeLine` 要判断 `end` 那行是不是闭合围栏，空代码块返回 `""`。
- 行号用纯 CSS counter：`.cm-codeblock { counter-increment: code-line }` + `.cm-codeblock-start { counter-reset }` + `::before { content: counter(code-line) }`；`.cm-codeblock-end::before { content: none }` 去掉闭合行的多余编号。
- 顶栏与代码块之间的空隙**不是 `<br>`**，是 CM6 在块级 widget 前后各插的 `img.cm-widgetBuffer` 把行撑开了。`.cm-line:has(.cm-code-bar) .cm-widgetBuffer { display: none }` 解决。
- `.cm-codeblock-start` 的圆角改 0，由顶栏负责上圆角。

预览图：`.workbuddy/preview/light.png` / `dark.png`。
