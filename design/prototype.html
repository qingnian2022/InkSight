界面设计基线

这份文件固定工作区的视觉契约。新增面板、控件与状态之前，先在这里找到它对应的角色；找不到，说明它还不该出现在界面上。

一、三条不可动的约束

  1. 正文是屏幕上唯一的主角，其余界面元素都要能退到背景里。
  2. 每个控件的存在都必须能回答「它解决哪一次重复操作」，回答不了就不放。
  3. 保存状态始终可见，不能用一闪而过的提示替代。

二、密度与节奏

工作区采用紧凑型工具密度：树行 28px、控件 28px、状态栏 28px，正文行高 1.8。密度的压缩只发生在非阅读区域，正文永远不为了塞下更多内容而缩小字号。

设计稿最容易骗人的地方，是它在理想内容下好看。验收必须用最长的中文标题、最宽的表格和空文件夹来跑。

2.1 行宽

正文测量宽度固定在 720px，约 40 到 45 个全角字符。超过这个宽度，眼球回扫会丢行；窄于 560px，长句会碎成太多行。行内代码写作 doc_save(docId, md, baseRev)，外部链接例如 Tauri 文档。

三、组件清单

  • 标签行：38px 高，承载已打开文件，未保存以 6px 圆点标记，悬停才出现关闭按钮。
  • 工具栏：40px 高，按「历史 / 行内格式 / 块级格式 / 插入」四组排列，组间用 1px 分隔线。
  • 图标按钮：28×28，必须带 aria-label，同一界面只用一套描边图标。
  • 树与编辑器联动
  • 保存状态四态
  • 表格渲染，排到 P1

四、渲染管线

即时渲染只做装饰，不改变文档结构。光标所在行保留原始语法，其余行隐藏标记，这样任何一次格式化都不会写回文件。

// 光标所在行跳过替换，其余行只加装饰
const active = linesWithSelection(state);
const ranges = visibleLines(view).flatMap((line) =>
  active.has(line.number) ? [] : decorate(line)
);

五、验收口径

**当前块始终显示原始标记**，光标离开该行后才隐藏；关闭即时渲染，正文应退回等宽源码且一个字都不丢。

这一条是整份设计的底线：渲染是视图层的事，文件内容不因视图改变。
